# Toowix Mail Platform — DNS & Domain Setup Guide

This guide details the required DNS configuration for organizations hosting email on the Toowix Mail Platform.

---

## 1. Domain Registration & Tenant Binding Policy

* **Hard Invariant**: **1 Tenant = Exactly 1 Primary Domain**.
* **Explicit Domain Activation**: The domain is **not** created in Stalwart or given any DNS at registration or approval time. It is created in Stalwart, assigned RSA/Ed25519 DKIM signing keys, and has its DNS records generated and published to the customer's DNS provider only when a Super Admin explicitly clicks **Activate Domain** for that domain. Registering or approving a tenant never touches Stalwart or public DNS.
* **GoDaddy Authorization**: The Tenant Admin supplies a GoDaddy API key/secret scoped to their own domain before activation can proceed. Toowix verifies the credential actually manages the entered domain before storing it (encrypted, and only for the duration of the activation attempt), and discards it once the domain reaches `active`.

---

## 2. Standard DNS Records Configuration

For a tenant domain (e.g. `acme.com`), the organization's DNS provider (Cloudflare, Route 53, Namecheap, etc.) must publish the following records:

### A. Inbound Mail Routing (MX Record)
Directs inbound SMTP email to the Toowix mail platform cluster.

| Type | Host / Name | Value / Target | Priority | TTL |
|---|---|---|---|---|
| **MX** | `@` (or `acme.com`) | `mail.toowix.com` | `10` | 300 / Auto |

---

### B. Sender Policy Framework (SPF Record)
Authorizes the Toowix mail servers to send email on behalf of your domain, preventing spoofing.

| Type | Host / Name | Value / Text Content | TTL |
|---|---|---|---|
| **TXT** | `@` (or `acme.com`) | `v=spf1 mx include:_spf.toowix.com ~all` | 300 / Auto |

*Note: If sending exclusively through Toowix, `v=spf1 mx ~all` is valid.*

---

### C. DomainKeys Identified Mail (DKIM Records)
Cryptographically validates that outgoing email was signed by your authorized Stalwart server and has not been altered in transit. Stalwart generates **two** active DKIM keys per domain (RSA and Ed25519) with a **dynamic, per-domain selector** — there is no fixed `toowix._domainkey` host name. Both records must be published.

| Type | Host / Name | Value / Text Content | TTL |
|---|---|---|---|
| **TXT** | `<selector>._domainkey` (e.g. `v1-rsa-20260907._domainkey`) | `v=DKIM1; k=rsa; p=<PUBLIC_KEY>` | 300 / Auto |
| **TXT** | `<selector>._domainkey` (e.g. `v1-ed25519-20260907._domainkey`) | `v=DKIM1; k=ed25519; p=<PUBLIC_KEY>` | 300 / Auto |

*The exact selector and public key are generated by Stalwart per domain and shown in the Tenant/Super Admin activation UI — never guess or hardcode them.*

---

### D. Domain-based Message Authentication (DMARC Record)
Enforces policy on how receiving mail providers (Gmail, Microsoft 365, Yahoo) handle messages failing SPF or DKIM.

| Type | Host / Name | Value / Text Content | TTL |
|---|---|---|---|
| **TXT** | `_dmarc` | `v=DMARC1; p=none; rua=mailto:dmarc-reports@acme.com` | 300 / Auto |

Toowix publishes `p=none` (monitoring-only) automatically at activation, so a new domain's mail is never silently dropped before SPF/DKIM alignment is confirmed. *Recommended manual progression thereafter:*
1. Initial deployment (set by Toowix at activation): `p=none` (Monitoring mode).
2. Quarantine mode: `p=quarantine; pct=100`.
3. Strict enforcement: `p=reject; pct=100` (Production standard).

---

### E. Client Autoconfiguration (IMAP & SMTP Autodiscover)
Enables Thunderbird, Apple Mail, Outlook, and mobile clients to configure mailboxes automatically.

| Type | Host / Name | Target / Value | Port | Priority | Weight |
|---|---|---|---|---|---|
| **SRV** | `_imaps._tcp` | `mail.toowix.com` | `993` | `0` | `1` |
| **SRV** | `_submission._tcp` | `mail.toowix.com` | `587` | `0` | `1` |
| **CNAME** | `autoconfig` | `mail.toowix.com` | — | — | — |
| **CNAME** | `autodiscover` | `mail.toowix.com` | — | — | — |

## 3. DNS Verification Commands

Verify propagation using `dig` or `nslookup`:

### 1. Verify MX
```bash
dig +short MX acme.com
# Expected output: 10 mail.toowix.com.
```

### 2. Verify SPF
```bash
dig +short TXT acme.com
# Expected output includes: "v=spf1 mx ~all"
```

### 3. Verify DKIM
```bash
dig +short TXT <selector>._domainkey.acme.com
# e.g. dig +short TXT v1-rsa-20260907._domainkey.acme.com
# Expected output includes: "v=DKIM1; k=rsa; p=..." (and a second lookup for the ed25519 selector)
```

### 4. Verify DMARC
```bash
dig +short TXT _dmarc.acme.com
# Expected output: "v=DMARC1; p=none; ..." immediately after activation
```
